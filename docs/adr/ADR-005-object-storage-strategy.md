# ADR-005: Object Storage Strategy

## Status

Accepted

## Context

Lessons will include images and documents. Files must not be treated as executable app content. Local filesystem coupling would hinder deployment.

## Decision

Define domain port `ObjectStorage`.

- Production/local target: **S3-compatible** API (MinIO locally)
- Tests: in-memory adapter
- Object keys generated by the application (never trust upload filenames)
- MIME allow-list and size limits at the application boundary when uploads exist
- Access via API-issued URLs or authenticated download, not public-executable paths

Malware scanning is a future hook, not implemented.

## Alternatives

- Only local filesystem: simple, blocks cloud object storage
- OpenSearch for files: wrong tool
- Trusting `Content-Type` from the client without checks: unsafe

## Consequences

- Health of the API does not require MinIO (storage is optional for Phase 2 status)
- Upload UI is not built yet; the port exists so later code does not hardcode disks
